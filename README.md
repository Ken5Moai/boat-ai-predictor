# ボートAI予想ツール v16 STRUCTURED

スマホ（iPhone Safari）中心で使う、3連単の買い目を6点以内に絞るWebアプリ。

公開URL: https://ken5moai.github.io/boat-ai-predictor/

- 構成: `index.html` 1ファイルのみ（GitHub Pages / mainブランチ / ルート）
- 外部依存: Tesseract.js v5（OCR補助）のみ

## 使い方（この順番で進めてください）

| STEP | やること | 手入力 |
|---|---|---|
| 1 | 開催日・競艇場・レース番号を選ぶ | 選択のみ |
| 2 | **6艇の登録番号を入力** →「公式照合」 | ★ここだけ |
| 3 | 出走表データを入れる（下の3つの方法から1つ） | なし〜 |
| 4 | 「コース別成績を取得」 | なし |
| 5 | 展示・水面気象（3で取れていれば不要） | 風向のみ |
| 6 | 6艇カードでデータを目視確認 | 必要なら修正 |
| 7 | 「予想レポート生成」 | なし |

手入力するのは**登録番号だけ**。選手名・級別・勝率・モーターは自動取得します。

## 競艇場の実測データ

STEP1の「この競艇場のデータを取り込む」を1回押すと、公式の
ボートレース場データページから次を取り込みます。

- コース別入着率（1着〜6着率）
- コース別決まり手（逃げ・捲り・差し・捲り差し・抜き・恵まれ）
- 枠番別コース取得率（枠なり進入の多さ）
- 季節別のコース別入着率（春夏秋冬）
- 水質・干満差

取り込むと**枠の評価が推測値から実測値に変わります**。開催日から季節を
判定し、その季節の数値を使います。一度取り込めば端末に保存され、
次回から通信不要です。24場すべてを手作業でアップロードする必要はありません。

データ元（全場一覧）:
https://www.boatrace.jp/owpc/pc/extra/data/stadium/index.html

各場の個別ページURLは、この一覧ページのリンクをたどって自動で探します。
一度見つけたURLの形は記憶し、次の場からは直接開きます。
サイト構成が変わってもリンクをたどるため壊れにくい作りです。
取得できない場合は、ページをコピーして貼り付けても取り込めます。

取り込まなくても予想はできます（その場合は目安の数値を使います）。
多摩川は初期データとして収録済みです。

各行の合計が100%になるかを検算し、合わない行は採用しません。

## 進入コース（スタート展示）

スタート展示では、枠番どおりの並びにならないことがあります。
例: 並びが 1-2-3-5-6-4 なら、4号艇は6コースを走ります。

このアプリは**枠番ではなく実際に走るコースで採点します**。

- 4号艇が6コースなら、6コースの入着率・6コースの選手実績で評価
- 外へ下げられた艇は減点、前付けで内を取った艇は加点
- 進入が崩れているほど本番も読みにくいため、買い目を広めに散らす
- 信頼度を1段下げる

直前情報を取得すると自動で反映されます。取得できない場合は
STEP5の「進入並び」に `123564` のように入力してください
（1文字目＝1コースの艇番）。

## 今節成績（節が進むほど効く）

出走表から、その節で走った各レースの「進入コース / ST / 着順」を
自動で取り込みます。位置ではなく、この3点セットという形で拾うため、
勝率やモーター番号と取り違えません。

予想に使うのは次の3つです。

| 項目 | 内容 |
|---|---|
| 今節着順 | 平均着順。良いほど加点 |
| 今節平均ST | 公式の平均STより新しい情報 |
| 今節の調子 | 節の前半と後半を比べ、上向きか下降か（**4走以上で初めて採点に入る**） |

**重みは走った本数に応じて増えます**
（0走で0、1走1/6、3走1/2、6走で満額）。
初日は今節成績を使わず、日が進むほど比重が上がる設計です。

「今節の調子」は3走以下では **1.5走 対 1.5走** の比較になり、
ほぼ雑音になります。徳山1Rでは3走しかない6号艇が94点・3号艇が100点を取り、
どちらも下位に敗れました。そのため4走から採点に入れます。

そのため、**3〜5日目の予選**が最も判断材料が揃います。
準優勝戦・優勝戦は上位が揃って実力差が縮まり、配当も下がるため、
的中率は上がっても期待値は下がりやすい点に注意してください。

手入力した場合は自動取得より優先されます。

## 予想に必要な項目

| 項目 | 必須 | 理由 |
|---|---|---|
| 登録番号 | ★ | 艇と選手を結ぶ絶対キー |
| 級別 | ★ | 採点に使用 |
| 全国勝率 | ★ | 採点に使用 |
| 当地勝率 | ★ | 採点に使用 |
| モーター2連率 | ★ | 採点に使用 |
| 選手名 | — | 表示とOCR照合のみ。**無くても予想できる** |
| 展示・コース別・気象 | — | 取れた分だけ加点 |

選手名は採点に一切使いません。名前が読めないだけで予想できなくなるのは
おかしいため、必須から外しています（入れておくと展示スクショの照合精度が上がります）。

## 結果の記録（STEP8）

予想レポートを作ると自動で保存されます。レース後に着順を入れると、
3連単・3連複・1着の的中率、回収率、信頼度ごとの成績が出ます。

**結果を見てから採点の重みを変えるのは、本来やってはいけない調整です。**
予想を先に残しておくことで、「たまたま当たった」と「本当に効いている」を
区別できるようにしています。信頼度Aの的中率が実際に高いのかも確認できます。

記録は端末にのみ保存されるため、ときどき書き出して保存してください。

### 何番目に評価されていたか

予想時の120通りすべての評価順を保存しています。結果を入れると、
実際の着順が何番目の評価だったかが分かります。

- 平均が10番目あたり → 評価は合っている。**点数を増やせば当たる**
- 平均が30番目以上   → **採点の重みを見直す必要がある**

「6点なら / 10点なら / 20点なら当たっていた率」も出るので、
買い目の点数を決める材料になります。点数はSTEP1で4〜12点から選べます。

## 採点の検証（backtest.js）

実際に走ったレースのデータで、結果が120通り中何番目に評価されていたかを
測るスクリプト。重みや評価バンドを変えた時の影響を数字で確認できる。

```

```

**重みは思いつきで変えず、必ずこれで測ってから変える。**
採点の重みは `W`、評価の上下限は `BAND` に集約してある。

### 展示の進入は「決定」ではない

徳山6Rでは、スタート展示の進入が **1-2-6-3-4-5**（6号艇が3コースまで前づけ）
だったのに対し、本番は **1-6-2-3-4-5** とさらに動いた。
6号艇が2コースまで入り、押し出された2号艇が3コースからまくって1着。

採点は「実際の進入が分かっている場合はそれを事実として扱う」設計だが、
**進入争いが起きている展示では、その進入自体が確定ではない**。

答え合わせとして、本番の進入を教えた場合も測った。

```
展示の進入で採点   6(66.0) 2(63.9) 1(63.7) 4(56.2) 3(42.5) 5(37.4)  → 37番目
本番の進入で採点   6(70.1) 1(63.7) 2(56.4) 4(56.2) 3(42.5) 5(37.4)  → 51番目
```

**本番の進入を知っていても、もっと外していた。** 原因は進入の読み違いではなく、
「押し出された艇は不利（−3.5）」という補正のほうだった。
内が前づけで詰まると、外に出された艇のまくりが決まることがある。
この補正も `▼未検証▼` として点検表に載せた（該当6件）。

### 当たっても負ける — その正体

的中した9レースを、モデルの確率と市場の確率で並べるとこうなる。
市場の推定確率は `0.75 ÷ オッズ`（3連単の控除率25%を戻した値）。

| レース | 結果 | 配当 | モデル | 市場 | 期待値 | |
|---|---|---|---|---|---|---|
| 桐生9R | 1-3-2 | ¥4,100 | 3.1% | 1.8% | **1.25** | ★ |
| 徳山2R | 3-1-2 | ¥4,240 | 4.6% | 1.8% | **1.97** | ★ |
| 徳山3R | 1-6-4 | ¥1,020 | 10.9% | 7.4% | **1.11** | ★ |
| 桐生8R | 1-5-4 | ¥1,400 | 2.9% | 5.4% | 0.40 | |
| 桐生12R | 1-5-4 | ¥10,960 | 0.6% | 0.7% | 0.70 | |
| 徳山1R | 1-2-4 | ¥790 | 4.4% | 9.5% | 0.35 | |
| 徳山4R | 1-2-4 | ¥890 | 7.2% | 8.4% | 0.64 | |
| 徳山5R | 1-3-4 | ¥2,060 | 1.5% | 3.6% | 0.32 | |
| 徳山6R | 2-3-6 | ¥5,660 | 0.7% | 1.3% | 0.41 | |

**期待値1.00以上だった3レースが、そのまま黒字だった3レース。**
赤字だった的中は例外なく、市場のほうがモデルより自信を持っていた組だった。

問題は予想精度ではない。**オッズを見ずに買っていたこと**。

回収率 ＝ 確率 × オッズ なので、オッズを見ないかぎり
どれだけ当てても勝てるかどうかは決まらない。
モデルが市場より正確である必要はない。**市場と違うところで正しければよい。**

### 対策：確率順ではなく期待値順に買う

STEP7にオッズ入力を置いた。使い方は次のとおり。

1. 一度「予想レポート生成」を押す（候補30点が出る）
2. 各行の **「○○倍以上」** が損益分岐。確率の逆数
3. 公式のオッズ画面を見て、**それを超えている組だけ**オッズを入力する
4. もう一度「予想レポート生成」を押す → 期待値の高い順に買い目が選び直される
5. 期待値が基準（既定1.10）に届く組が無ければ **「見送りを推めます」** と出る

オッズを1つも入れなければ、これまでどおり確率順で選ぶ。
その場合も各買い目に損益分岐オッズを出すので、手元で外すことができる。

なお、**的中した組に付いていた確率の平均はモデル4.0% / 市場4.4%**で近い。
モデルは市場と同程度には校正されている、という弱い証拠にはなる。
9レースでは何も断定できないので、ここから先は記録で確かめる。

### 検証のしかた：期待値ごとの回収率

STEP8の記録に、買った各点の**オッズと期待値**を残すようにした。
記録画面に「期待値ごとの回収率」の表が出る。

| 買った時の期待値 | 点数 | 的中 | 購入 | 払戻 | 回収率 |
|---|---|---|---|---|---|

**この表の「1.00以上」の帯が100%を超えるかどうかが、すべての答え。**

- 超える → モデルの確率は市場より正確。期待値で買えば勝てる
- 超えない → 期待値の計算に使っている確率がまだ当てになっていない

点数を増やすことでも、重みをいじることでもない。
30点ぶんくらい貯まったところで読めるようになる。

### 失敗した仮説：スコア差から配当を予想する

6レースの時点で「1位と2位のスコア差が小さいレースほど配当が高い」
という関係が見えたので、レポートに配当の規模を助言する機能を入れた。

**7レース目（徳山4R）で外れた。** 差4.8（小さい＝荒れる想定）に対して
実際の配当は¥890（2番人気）だった。

| スコア差 | レース | 配当 |
|---|---|---|
| 2.3 | 徳山2R | ¥4,240 |
| 3.5 | 桐生12R | ¥10,960 |
| **4.8** | **徳山4R** | **¥890** ← 外れ |
| 11.4 | 徳山1R | ¥790 |
| 12.2 | 桐生9R | ¥4,100 |
| 12.6 | 桐生8R | ¥1,400 |
| 19.2 | 徳山3R | ¥1,020 |

8レース目（徳山5R、差13.8）は¥2,060。相関係数は -0.53。向きは合っているが、方向を断定できる強さではない。
**配当の規模を予想する機能は取り下げた。** 残したのは損益分岐の計算
（常に正しい）と、実測の配当分布だけ。

これは「少ない件数で見えた傾向を採用してはいけない」という
このプロジェクトの原則そのものを、自分で破って自分で確かめた例。
重みについても同じことをしない。

## 手書き補正の点検

採点の重み（`W`）と評価バンド（`BAND`）のほかに、
F持ち・展示F・チルト・部品交換・風・波・潮の**手で書いた加減点**がある。
これらは結果から決めたものではないので、`node backtest.js` が
毎回「何件に当たっていて、外すと順位がどう動くか」を出す。

実測8レース48艇の時点では、次のことが分かっている。

| 補正 | 該当 | 状態 |
|---|---|---|
| F持ち −4.0/本 | 13件 | **外すと平均11.4→10.6**。値が大きすぎる可能性 |
| 展示F −3.0 | 15件 | 外すと平均11.4→11.1。効いている |
| チルト0.5以上 ±3.0 | **1件** | 検証不能。その1件は最下位に敗れた |
| 部品交換 −1.5 | 3件 | 検証不能 |
| L持ち −2.5/本 | **0件** | **一度も発動していない** |
| 風（風速4m以上） | **0件** | **一度も発動していない** |
| 波（波高5cm以上） | **0件** | **一度も発動していない** |
| 潮 | **0件** | **一度も発動していない** |

**8つのうち4つは一度も発動しておらず、正しいかどうか確かめられていない。**
コード中には `▼未検証▼` と書いてある。消してはいないが、
これらが効いた予想は信用度が一段下がると考えること。

### F持ちの減点：8レースで見えた傾向は、9レース目で消えた

8レースの時点では、F持ちの減点を小さくするほど平均順位が良くなり、
しかも単調だった（−4.0で11.4 / −2.0で11.1 / −0.0で10.6）。
それでも「12点での的中数がどの値でも変わらない」ことを理由に値を変えなかった。

9レース目（徳山6R）を足すと、こうなった。

```
-4.0 → 14.2    -2.0 → 14.0    -0.0 → 14.2
```

**単調な傾向は消え、横ばいになった。**
徳山6Rでは1号艇（F1持ち）が本番ST .32 で最下位、
6号艇（F1持ち）も .19 で3着。F持ち2艇がそろってスタートを緩めた。
減点を外すと、このレースの順位は 37番目 → 43番目 と悪化する。

**8レースで見えた「単調な傾向」は偶然だった。**
これは「少ない件数で見えた傾向を採用しない」という原則が、
実際に損を防いだ一例。同じ判断を続けること。

## 設計ルール（場当たり修正を防ぐための約束）

過去に繰り返した「艇番ズレ・列ズレ・誤読」を構造で封じています。
修正するときも、このルールは崩さないでください。

1. **登録番号が絶対キー**。データは配列の位置ではなく登番で艇に紐付ける。
2. **艇は常に6件固定**。取得できなくても詰め上げない・並び替えない。
3. **未取得は空欄**。0で埋めない。
4. **形状ベース解析**。「何列目か」ではなく「値の形」で項目を判定するため、
   公式サイトのclass名や列順が変わっても壊れにくい。
5. **曖昧なら採用しない**。6艇ぶん揃わない展示STは一切入れない。
6. **異常値は不採用**。全国勝率0.16などは範囲外として弾く。
7. **信頼度の順位**: 手入力 > 公式 > 照合 > OCR。低い方が高い方を上書きしない。
8. **登番を変えたらその艇のデータは全消去**。前の選手の数値を残さない。
9. **OCRは補助のみ**。展示・気象・今節成績だけ。登番/選手名/勝率/モーターはOCRしない。
   OCR結果は位置ではなく**選手名→枠番**の順で艇に割り当てる。
10. **場名はレース指定から取得**。選手の支部（福岡など）から推測しない。
11. **コース関連の重みは合計一定**。枠（場の実測入着率）と選手のコース別成績は
    ひとつの枠として合計 0.34 を持ち、どちらが取れても合計は変わらない。
    以前はコース別成績（0.20）が未取得だと再正規化でそのぶんが消え、
    コースの比重が 0.34 → 0.175 とほぼ半分に縮んでいた。
    その結果、**6コースの艇がモーターと展示と今節が良いだけで2番手評価**まで
    上がってしまった（徳山1Rの6号艇は最下位に敗れた）。
    「未取得を0で埋めない」の裏返しで、
    **未取得が別項目の比重を勝手に下げるのも禁止**。
12. **「値が無い」と「記録が存在しない」を区別する**。
    当地勝率 0.00 はその場に初出走という意味で、取得失敗ではない。
    同じ扱いにすると、新人が1人いるだけでレース全体の信頼度が落ちる。
    採点では項目ごと外して重みを配り直し（0点にはしない）、
    必須チェックは満たしたものとして扱う。`localNone` で持つ。

## 予想ロジック

- 取得できた項目だけで重みを100%に再配分して採点（未取得を0点にしない）
- コース別成績は「そのコースで現実的に取りうる幅」で正規化するため、
  1号艇でもイン成績が悪ければ評価が下がる
- 競艇場のイン率・水質・風・波・潮で補正
- Plackett-Luceモデルで3連単120通りの確率を算出し、上位6点に絞る
- 金額は確率比例で配分（オッズを入れると期待値ベースに切替）

## スマホだけで完結させる方法（パソコン不要）

通信が不安定でも、スクリーンショットだけで予想まで到達できます。

1. STEP2で6艇の登録番号を入力
2. STEP3の「出走表ページを開く」→ **スクショを撮る**（複数枚でOK）
3. 「スクショから読み取る」を押す
4. STEP6のカードで数値を見比べて確認（違えばタップして直す）
5. STEP7で予想生成

登録番号を目印に読むため、**艇番がズレることはありません**。
読めなかった項目は空欄のまま残り、0で埋めることはしません。

## 取得できない時

無料のCORSプロキシは停止・制限が頻繁に起きるため、
自動取得が失敗することがあります。次の順に試してください。

1. **STEP3の「通信テスト」** … どの経路が生きているか実測します
   - 全滅する場合は `PROXY_SETUP.md` の手順で自分専用の取り出し口を作ると
     根本的に解消します（無料・10分）
2. **STEP3の「公式ページをコピーして貼り付け」** … 通信不要で確実
   - 公式ページを開く → 長押し → すべてを選択 → コピー
   - アプリに戻って貼り付け → 「貼り付け内容を解析」
   - HTMLでもMarkdownでもプレーンテキストでも解析できます
3. 各艇カードの欄に直接入力する（手入力が最優先で扱われます）
4. 診断ログを開いて「ログをコピー」

BR-RACERSや公式のURL構成が変わった場合は、
STEP4の「詳細設定」でURLテンプレートを書き換えるだけで復旧できます。
